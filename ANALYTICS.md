# Portfolio traffic analytics

The public portfolio files are unchanged. The Express server inserts `/tracking.js` when it sends the three HTML pages. It collects first-party per-browser visitors, pageviews, 30-minute visits, referrer hostname, five UTM tags, screen size, browser/platform and visible time. Do Not Track browsers and known user-agent bots are excluded. IPs are HMAC-hashed, not saved in plaintext. Local GeoIP lookups are approximate, especially behind VPNs. Metrics group days in Asia/Manila. Tracking begins at deployment, without historical backfill. No visitor cookies are shared with third-party services.

Run `npm start` or `server/run.sh`. Boot persistence is configured in `/.hako/init.sh` on port 8082. Keep `.env` mode 600 and `/home/kit/portfolio-data` mode 700, outside the public directory. The server has an explicit static-file allowlist; `.env`, git metadata, source and databases are never served.

The admin is `/admin`. `.env` contains `ADMIN_PASSWORD_HASH` (bcrypt, never plaintext), `SESSION_SECRET`, `IP_SALT`, `PUBLIC_ORIGIN`, `ANALYTICS_DATA`, and `PORT`. Use a bcrypt cost of 12 or greater when changing the password. The owner-exclusion cookie survives logout so browsing while signed out still does not count. Clearing browser cookies creates a new visitor and removes that exclusion until the next login.

Admin sessions are server-side SQLite, one year, HttpOnly/Secure/SameSite=Lax, regenerated on login and destroyed on logout. They expire server-side even if a client replays an old cookie. Expired records are purged hourly. To revoke all devices, stop the service and clear the `express_session` table in `/home/kit/portfolio-data/sessions.sqlite`, then restart. Rotate `SESSION_SECRET` if it is compromised. Do not manipulate an active database with a second process.

The login endpoint checks same-origin POSTs, uses bcrypt verification, generic errors, a 10-per-15-minute transient IP limit and database-backed backoff from the fifth failed attempt (30 seconds, doubling to one hour). Failed attempts are logged without passwords or raw IPs. Logout requires a constant-time CSRF token comparison. Admin HTML/API/assets are no-store and noindex; robots disallows admin/API routes. Helmet provides security headers. Admin has a strict CSP, while public CSP is unchanged to preserve its existing inline code and remote resources. HTTPS is terminated at the hosting proxy.

Checks are `npm run check`, `npm test`, and `TEST_PASSWORD=<admin password> node server/integration.cjs`. The integration suite uses a temporary isolated database and server, proving protected APIs, forbidden files, same-origin enforcement, owner exclusion, persistent login across restart, secure year-long cookies, CSRF, logout revocation and failed-login backoff across restart. Never run the integration suite against production data. Browser QA uses a `qa-portfolio-*` UTM campaign; remove only these fixture visits after safely stopping the server and backing up the database.
